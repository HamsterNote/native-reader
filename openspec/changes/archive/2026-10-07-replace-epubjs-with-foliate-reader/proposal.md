# Proposal

## Effective acceptance scope — HAM-35, 2026-10-16

Owner 修勾 explicitly authorized Web-only acceptance: “应标记为不需要真机测验，只需要 web 端验证即可” (comment `01a14506-b079-70fc-8e3c-824e7e47d27b`, delegated by `01a14508-6b02-7d14-b8ce-38b0bbd79005`). See `OWNER_WAIVERS.md` for the complete disposition. Real Android/WK transport, restricted-file origin, named-world relay, permission/navigation behavior, actual iOS initial-CSP integration, device multi-format evidence, isolated Robolectric/Apple XCTest, and unavailable real macOS/iOS Safari acceptance are waived/removed, not passed. Existing security requirements remain mandatory whenever a platform is enabled. In particular, an unproved iOS publication boundary remains unsupported before source I/O; this waiver does not enable iOS rendering.

The development-order dependency on obtaining device evidence is removed. Local 4C/4D implementation and JVM/browser/export/package validation remain required. Bind stays source-free; only the independent behavior probe authorizes bounded reads. The later 4C extension adds closed `probe` and `transfer` commands inside `hn-foliate-host` v1 without changing the native ABI. Bare `hn-foliate-transfer` remains invalid. The 4B prohibition on implementing later phases describes the historical skeleton milestone, not the completed 4C/4D runtime.

## Why

The current reader depends on `epubjs` on Web and `@epubjs-react-native/core` on iOS and Android, restricting the shipped contract and all acceptance assets to EPUB. HamsterNote needs one maintained upstream reader engine that can render the agreed local e-book formats on every target while retaining an auditable security boundary for untrusted publication content.

## What Changes

- **BREAKING** Replace the `epubjs` and `@epubjs-react-native/core` runtime integrations with the official `johnfactotum/foliate-js` source pinned as the `vendor/foliate-js` Git submodule at commit `78914aef4466eb960965702401634c2cb348e9b1`; remove the replaced packages, overrides, patches, staging assumptions, and EPUB-engine-specific consumer fixtures.
- **BREAKING** Expand the controlled local-source contract and Demo selection flow from EPUB-only to DRM-free EPUB, MOBI, KF8/AZW3, FB2/FBZ, and CBZ. PDF is expressly outside this change even though Foliate exposes an experimental PDF adapter.
- **BREAKING** Render Foliate inside a reader-owned, same-origin iframe host on Web and in the existing native secure-WebView boundary. The outer Web iframe loads the deterministic `public/reader/reader.html` shell without a required-CSP `csp` attribute; `reader.html` retains its versioned host meta CSP, and runtime manifest/hash/package-public synchronization continues to establish static-host integrity. This host policy does not replace publication policy. The shell runs the behavioral probe, then Web Foliate is Chromium-only: it runs only after the probe proves that an inner `iframe[csp]` blocks default-deny script plus same-origin and cross-origin request canaries. Only the untrusted publication blob iframe receives the strict required-CSP policy. Firefox and Safari/WebKit report a clear secure-browser-unsupported error without opening Foliate or accessing the selected publication. The runtime contains initial-CSP `reader.html`, external `bootstrap.js`, and the Foliate ESM closure; it never mounts `foliate-view` in the application document. Preserve `ReaderChrome` as the host chrome and retain only authenticated, host-controlled messaging through the Web iframe protocol and the existing `HNSecureWebViewModule` ABI.
- **BREAKING** Native secure Foliate hosting supports iOS 14+ only; the implementation will raise the iOS deployment target accordingly and has no page-world bridge fallback for earlier releases. The React Native adapter is the sole authority that generates every exactly-43-character base64url session, generation, and command ID, and sends `bind` over the platform-private transport; native code only validates, routes, and owns port/relay lifecycle, and must neither generate nor implicitly bind those tokens. iOS must use a normalized canonical restricted `file:` host-frame URL, exact current main-frame URL, and named isolated `WKContentWorld` relay. That relay injects its private port into the generated native host bootstrap and lexically calls `installFoliateNativeHostBridge(port)`, so iOS and Android use the same host-protocol endpoint rather than platform-specific endpoints. Its synthetic initial-CSP capability preflight is a strict behavioral control that runs before any publication URI/read/copy/transfer I/O and fails as stable unsupported with terminal relay teardown. Native hosts establish the strict publication CSP before Foliate generates any untrusted publication document blob, including EPUB HTML/XHTML/SVG, MOBI/KF8, FB2/FBZ, and CBZ paths, and prove that boundary with behavior probes. iOS may use `WKContentRuleList`, network blocking, load-after-meta, and scrubbing only as defense in depth. Android uses its current exact-origin `WebMessageListener` only to prove 4A capability, then clean-reloads into a native-owned private main-frame `WebMessagePort` channel with no `ReactNativeWebView`, parent-accessible equivalent, public global, or fallback. Its preserved `postMessage`/`onMessage` ABI closes over only the active private port; legacy generic mode may preserve page messages, but secure Foliate hosting cannot use that path. Android WebViews that cannot prove this final bridge and the embedded-CSP behavior probe fail closed; `addJavascriptInterface`, wildcard origins, and broad asset paths are not fallbacks.
- **BREAKING** Native source input is bounded to 32 MiB and crosses the secure host only through a session/generation/transfer-bound `begin`/chunk/`commit`/`abort` protocol with canonical format/name/MIME, byte length, SHA-256, finite chunk and total limits, and strictly contiguous sequence numbers. Stale, out-of-order, oversized, checksum-invalid, or aborted transfers do not create or update a reader session. Stage 4B establishes only adapter-authoritative `bind`/acknowledgement, terminal, and no-op semantics; it performs no source transfer and does not claim renderer `ready`.
- Make reflowable books open in `scrolled` flow by default on mobile, expose a user-facing switch to `paginated`, and retain `scrolled` as the accessible recovery mode. The change documents and tests that Android WebView pagination and text selection have upstream limitations; it does not promise a CSS-only correction.
- Replace EPUB-specific fixtures, generators, E2E flows, packaging checks, and documentation with a deterministic multi-format corpus and verification paths that distinguish browser evidence, bundle/export evidence, and any separately collected native-device evidence.
- Split Web acceptance into a completed automated baseline and an open release/platform gate. The baseline is CFT Chromium evidence plus static-export and packed-consumer checks; it does not assert real branded Edge, real macOS Safari, real iOS Safari, development-server, runtime-asset-missing browser E2E, or complete package raw-environment evidence. The open release/platform gate does not represent acceptance success, but it does not prevent the independent native Stage 4 work from starting.

## Capabilities

### New Capabilities
- `local-multi-format-reading`: Opens supported local e-book formats, normalizes their navigation, and applies the mobile reading-flow contract.
- `foliate-reader-security`: Constrains untrusted Foliate-rendered publication content across browser and native WebView hosts.
- `foliate-reader-supply-chain`: Vendors the official Foliate source as a reproducible, pinned Git submodule and excludes replaced engine supply-chain artifacts.

### Modified Capabilities
- `reader-component-api`: Replace the obsolete placeholder and EPUB-only component requirements with the multi-format controlled-source, observable-state, navigation, and reading-flow public contract.
- `cross-platform-reader-demo`: Replace EPUB-only Demo selection and EPUB-only acceptance requirements with the supported-format picker, fixture corpus, and qualified cross-platform verification requirements.

## Impact

- Affected library code includes `packages/native-reader/src/NativeReader.web.tsx`, `NativeReaderImplementation.native.tsx`, shared types/model code, `ReaderChrome.tsx`, the Web iframe protocol, and secure-WebView bridge usage.
- Affected application and quality assets include the generated `foliate-runtime/web/` source, deterministic runtime manifest and sync/check scripts, each host project's `public/reader/` output, `apps/demo/src/DemoApp.tsx`, format-neutral fixtures, Playwright tests, package/consumer fixtures, root scripts, package manifests, PNPM overrides/patches, notices, and documentation.
- Expo 57 Web workspace development, exported Demo output, and a packed external consumer must each explicitly materialize and verify the runtime at that consumer's project-root `public/reader/`; Metro asset loading, webpack, `assetExts` changes, package-external `EXPO_PUBLIC_FOLDER` symlinks, blob/data bootstraps, and consumer-installed global loaders are not integration options.
- Browser support is intentionally narrowed to Chromium implementations that supply real-browser evidence for the inner required-CSP publication boundary. The completed automated baseline supplies CFT Chromium blocked-canary proof and Firefox fail-closed evidence; release acceptance remains open for real branded Edge blocked-canary proof and real macOS/iOS Safari unsupported-error and zero-publication-I/O proof. This change does not claim Firefox or Safari/WebKit publication rendering support, and Playwright WebKit is not evidence of Safari acceptance.
- The public `ReaderSource`, error/state vocabulary, and reader controls require a migration review by package consumers. No physical iOS or Android device result is asserted by this planning change; native bundle/export checks remain build evidence only.
- Native secure-host support will raise the iOS deployment target to iOS 14; this planning change does not claim implementation or device validation of that target change.
- Android serves generated runtime assets only through a manifest-exact `WebViewAssetLoader` allowlist at `https://appassets.androidplatform.net`; canonical-path/Unicode/URL-confused requests, unknown assets, and unapproved MIME types fail closed with explicit CSP, `nosniff`, and 404 handling. iOS reads only reader-owned runtime/cache roots. Neither platform's asset CSP replaces the publication CSP.
- `SECURE_WEBVIEW_SHA256.json`, or an equivalent staging-integrity record, is release evidence only when regenerated from and verified against the actual native runtime files included in the packed package; a source-tree-only manifest cannot establish shipped-runtime integrity.
