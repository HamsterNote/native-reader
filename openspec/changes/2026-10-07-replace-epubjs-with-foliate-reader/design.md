# Design

## Context

See `proposal.md` for motivation and the delta specifications for the behavioral contract. The current package has two EPUB-specific renderers: `NativeReader.web.tsx` imports `epubjs`, while `NativeReaderImplementation.native.tsx` imports `@epubjs-react-native/core` and feeds its generated document into a secure WebView. `ReaderChrome.tsx` already owns platform-neutral load state, chapter controls, TOC controls, accessibility labels, and the React Native viewport. `ReaderSource` is currently a local URI plus optional name and MIME hint.

`HNSecureWebViewModule` is an existing code-generated native ABI used for secure navigation decisions. Android's secure-WebView defaults deny file/content access; the reader cannot bypass that policy with direct file URLs. Foliate renders through Web Components, Shadow DOM, iframes, and blob URLs. Its upstream documentation requires CSP for untrusted EPUB content, calls PDF support experimental, and documents that its paginator uses CSS multi-column. Android WebView paginated rendering and selection therefore require an explicit scrolling recovery path rather than a promised CSS workaround.

Expo 57 Web preserves a project-root `public/` tree at stable relative URLs in both `expo start --web` and `expo export --platform web`. That property is required because Foliate is a multi-file native ESM graph: Metro `require`/`expo-asset` development query URLs and exported hashed URLs do not preserve its relative imports. The Web runtime must therefore be copied deterministically to the consuming application's `public/reader/`, not loaded as a Metro asset or supplied by consumer configuration.

The static reader host CSP protects the bootstrap document but cannot by itself impose a response CSP on Foliate's publication blob documents: blobs have no HTTP response, and a parser-added meta policy cannot reliably precede every XHTML, XML, or SVG path. W3C Embedded Enforcement through an inner `iframe[csp]` provides the needed publication initial-policy boundary, but it is experimental/limited availability and is implemented by Chromium 61+ rather than Firefox or Safari/WebKit. The outer reader iframe cannot itself carry a required-CSP `csp` attribute: an outer required-CSP prevents its stricter inner publication iframe from navigating to its blob document. The outer static shell instead retains its versioned host meta CSP and runtime manifest/hash/package-public synchronization. Those host controls protect shell code and asset integrity; they do not replace the required-CSP publication boundary. Feature presence (`'csp' in HTMLIFrameElement.prototype`) is not security evidence; the probe must run within the outer shell and runtime behavior must prove inner-frame enforcement before the reader accesses any publication.

## Goals / Non-Goals

**Goals:**

- Use only the official Foliate repository as the reader-engine source and make its revision, license treatment, and shipped assets auditable.
- Preserve one public React Native component and host-owned source lifecycle while moving all format parsing/rendering behind a common Foliate protocol.
- On Web, isolate Foliate and publication DOM from the application document with a reader-owned same-origin iframe, initial document CSP, Chromium-only behavior-proven embedded CSP enforcement, strict two-way messaging, and a reproducible public-runtime delivery path.
- Support the five approved local formats in behavior-proven Chromium Web sessions and on iOS/Android with content-aware detection, normalized host chrome, default native scrolling, optional pagination, and failure-safe cleanup.
- Apply platform-proven initial publication CSP, exact native bridge/message validation, and bounded source transfer before a publication can affect the reader session.
- Replace the EPUB-specific corpus and verification path with repeatable multi-format evidence without representing native export as native-device execution.

**Non-Goals:**

- PDF, remote publication URLs, DRM bypass, annotations, search, progress persistence, media overlays, and a guarantee that every publisher's malformed or encrypted file is readable.
- Repairing Foliate's multi-column paginator, Android WebView rendering, or text-selection defects upstream.
- Changing the `HNSecureWebViewModule` ABI, exposing Foliate as a public package subpath, or accepting DOM `File` objects in the package API.
- Webpack, Metro `assetExts` changes, package-external `EXPO_PUBLIC_FOLDER` symlinks, blob/data bootstrap documents, and consumer-installed global resource loaders.
- A best-effort, UA-sniffed, or feature-presence-only Web fallback for Firefox, Safari, or WebKit. A failed embedded-CSP probe is an unsupported browser outcome, not a permissive rendering mode.
- A native fallback to `addJavascriptInterface`, wildcard bridge origins, broad asset paths, post-load CSP insertion, document scrubbing, or network/content rule blocking as a substitute for the required initial publication CSP and behavior proof.

## Decisions

### 1. Vendor the official engine as a fixed Git submodule

Add `.gitmodules` with `vendor/foliate-js` pointing at `https://github.com/johnfactotum/foliate-js.git`, then commit the gitlink at `78914aef4466eb960965702401634c2cb348e9b1`. A supply-chain script will verify the configured URL, initialized worktree, clean submodule state, and exact `HEAD` before commands that build engine assets, run format tests, package the library, or create release artifacts. It will also require a tracked revision-review record whenever the gitlink changes.

Foliate is an upstream native-ES-module project with no stable release API and explicitly recommends a Git submodule. Runtime assets will be generated from that exact checked-out tree into a package-private build/staging location with their required official vendored modules and license notices, then included only as runtime assets needed by Web and native hosts. The build will not install `foliate-js`, `epubjs`, or `@epubjs-react-native/core` from npm.

Alternatives considered:

- An npm package for Foliate: rejected because the product decision requires the official source and immutable Git revision.
- Copying source into `packages/native-reader`: rejected because it obscures upstream provenance and makes revision review unreliable.
- Retaining the old engines per platform: rejected because it preserves divergent formats, security behavior, and stale third-party integration.

### 2. Use one Foliate integration protocol with platform-specific transport

Define an internal adapter contract that receives only a reader-owned representation of a validated host URI, returns normalized metadata/sections/TOC/location/load errors, accepts navigation and flow commands, and exposes deterministic disposal. The public `ReaderSource` remains host-owned; format, parser selection, and any temporary copies/blob URLs are derived state.

On Web, `NativeReader.web.tsx` creates only a reader-owned outer `<iframe>` in the existing viewport. It has an exact same-origin `src` for the synchronized `/reader/reader.html` runtime, not a generated query, blob/data URL, application-document mount of `foliate-view`, or a required-CSP `csp` attribute. Before the shell creates a publication blob iframe, calls Foliate open, or reads the publication URI, the shell runs a default-deny inner `iframe[csp]` behavior probe. The probe must prove that inner-frame script execution and both same-origin and cross-origin request canaries are blocked. Real-browser evidence has confirmed that the same blob iframe required-CSP blocks inline script and same-origin image loading at top level; the acceptance boundary remains the probe's inner-frame behavior in the outer shell. Only a passing probe permits the Chromium Web path; a failed or unavailable probe produces the explicit secure-browser-unsupported error with no publication blob iframe, Foliate open, or publication-URI access.

Each permitted inner publication frame, and no outer reader frame, receives the strict policy through embedded enforcement rather than a parser-inserted meta tag. The parent owns React state and sends a detector-normalized private `File`/`Blob`, never a URI string, to the iframe. The `open` schema accepts only an object containing a finite canonical `format` enum and its canonical filename/MIME tuple plus the private blob payload; it rejects every other type, string, URI, hint-only, or malformed object. `reader.html` loads the external same-origin `bootstrap.js`; the bootstrap imports only the staged Foliate ESM closure, creates `foliate-view`, and translates renderer events into the internal adapter protocol.

On iOS and Android, the existing `NativeReader.native.tsx` boundary continues to manage React Native lifecycle and `ReaderChrome`, without changing the `HNSecureWebViewModule` ABI. The React Native adapter is the single authority that generates exactly-43-character base64url session, generation, and command ID values, retains their current/inflight state, and originates each `bind`; native code validates those adapter-issued values, forwards wire data, and owns only private port/relay lifecycle. It loads a generated, package-private Foliate host document through `HNSecureWebView`, but a platform security gate must pass before the reader reads, copies, prepares, or transfers a selected source. Native secure Foliate hosting is iOS 14+ only; the eventual deployment-target increase has no `<14` page-world bridge fallback. The native bridge accepts events only from its authenticated private main frame and binds every message to the adapter-authoritative session, generation, and command ID.

Android's existing exact-origin `WebMessageListener` is limited to the 4A capability proof. After that proof, the native host clean-reloads and creates a native-owned private main-frame `WebMessagePort` channel. In secure Foliate mode, the preserved ABI `postMessage(data: string)` must route exclusively into the active private port and `onMessage` must emit exclusively from that port after validation; generic mode may retain its old page-message behavior, but no secure Foliate host message may use it. The final host exposes neither `ReactNativeWebView` nor a parent-accessible equivalent, public global, or fallback channel. Exact host URL, channel ownership, session, generation, command-ID, direction, duplicate, and inflight guards apply in both directions. Actual installed-WebView evidence must prove the final transport; unsupported behavior fails closed without source I/O. `addJavascriptInterface`, wildcard origins, and broad asset paths are never alternatives.

iOS uses a normalized canonical restricted `file:` host-frame URL and accepts relay traffic only where the security identity, exact current `WKWebView` main URL, expected handler, named `WKContentWorld`, and `frameInfo.isMainFrame` all match. The isolated world provides a main-frame-only private relay; it injects its private port into the generated native host bootstrap and lexically invokes `installFoliateNativeHostBridge(port)`. That generated bootstrap is the same host-protocol endpoint consumed by Android, not an iOS-specific endpoint; the preserved ABI `postMessage`/`onMessage` closes over the active relay port and has no page-world fallback. An actual `WKWebView` spike must prove the selected restricted file security-origin tuple and relay behavior before this design can rely on it. The synthetic initial-CSP capability preflight is a strict behavioral control performed before any publication URI/read/copy/prepare/transfer I/O; failure becomes stable unsupported, emits no `ready`, and terminally tears down the relay. It is a capability test, not publication ready and not permission to open a source.

Native preparation accepts at most 32 MiB. After the security gate and bounded detection have established the canonical format/name/MIME, prepared bytes cross the bridge only through an authenticated `begin`/chunk/`commit`/`abort` transfer bound to adapter-issued session, generation, command ID, and transfer ID. `begin` fixes finite byte length, SHA-256, chunk limit, total limit, and canonical metadata; chunks have strictly contiguous finite sequence numbers; `commit` verifies the exact byte count and digest. Stale, duplicate, skipped, oversized, checksum-invalid, malformed, or aborted transfer traffic cannot create or update a reader session. A native cache copy is reader-owned only when needed to turn a selected `file:`/`content:` URI into an input usable under the secure-WebView access policy. This transfer protocol does not exist in 4B.

Alternatives considered:

- Running Foliate directly in React Native JavaScript: rejected because Foliate needs browser DOM, custom elements, Shadow DOM, iframe, Blob, and CSS layout APIs.
- Replacing `ReaderChrome` with Foliate's example reader UI: rejected because it would duplicate host controls and weaken the existing public accessibility/test contract.
- Changing native bridge ABI: rejected because the current secure module already provides the synchronization boundary and changing it increases native release risk.

### 3. Detect content before parser selection and normalize only supported forms

The adapter will read a bounded leading byte range and necessary local structure through its platform transport, identify ZIP-based EPUB/CBZ, PalmDB-based MOBI/KF8/AZW3, XML/ZIP FB2/FBZ, and PDF signatures, then use names/MIME only for picker presentation and diagnostics. On Web it derives a private `File` or `Blob` with the detector's canonical parser filename and MIME before the iframe receives it; source hints cannot choose a parser or survive as parser identity. The public source URI remains owned by its host: the reader never revokes, deletes, or transfers ownership of it. Parser open failures map to shared categories that distinguish unsupported format, invalid/corrupt source, unsupported encrypted/DRM content, read failure, and render failure. PDF is rejected before any PDF adapter is imported or invoked.

Foliate's book interface becomes the internal normalization source: linear sections build host previous/next state, TOC is flattened with retained depth and destinations, and `foliate-view` `relocate` events use the actual `event.detail` location shape. KF8/MOBI TOC target resolution is asynchronous, including Foliate's fragment resolver, and remains session-guarded until it completes. Chrome previous/next means previous/next readable linear section, not an implementation pager's previous/next page. Image-based CBZ uses the fixed-layout renderer and exposes no reflow-flow control. For reflowable books the current session's renderer `flow` attribute is changed in place; the renderer-reported layout decides whether flow is available, never the detector's format guess. The adapter retains the current location through a flow change where the renderer can do so; if it cannot preserve an exact anchor, it reports the resulting observable location instead of claiming progress persistence.

Alternatives considered:

- Dispatching solely from extension/MIME: rejected because a user-controlled name or platform MIME can misclassify bytes.
- Treating PDF as a sixth supported format: rejected because Foliate documents its adapter as experimental and the product scope excludes it.
- Maintaining EPUB-only profile validation: rejected because the new supported formats do not share EPUB package metadata and need parser-level rejection semantics.

### 4. Deliver a deterministic same-origin Web reader runtime

The package-private generated runtime source will contain `foliate-runtime/web/reader.html`, its external `bootstrap.js`, and the closed set of Foliate ESM dependencies and retained notices. A deterministic manifest records every emitted relative path and integrity/checksum data. A sync command copies exactly that manifest to each host application's project-root `public/reader/`; a check command rejects a missing, stale, extra, or hash-mismatched runtime before Web start, Web export, demo verification, package verification, and packed-consumer verification.

`reader.html` is an actual static initial document with a CSP meta policy in the HTML before the external bootstrap module can run. It and its ESM closure retain stable relative URLs under `public/reader/`, so `expo start --web` and `expo export --platform web` serve the same relative import graph. The workspace Demo and a packed consumer explicitly run the sync into their own `public/reader/`; the library package does not assume that the consuming app can resolve package-private files by URL. This approach intentionally rejects webpack rewriting, Metro asset registration or `assetExts` configuration, package-external public-folder symlinks, and a global consumer loader.

Alternatives considered:

- Importing Foliate through Metro or `expo-asset`: rejected because development asset query strings and exported hashes break Foliate's relative ESM imports.
- Directly mounting `foliate-view` in the application document: rejected because publication DOM and renderer lifecycle would share the application's security boundary.
- Serving a blob/data bootstrap document or asking consumers to install a loader: rejected because it weakens initial-document policy/auditability and makes packed-consumer behavior non-deterministic.

### 5. Constrain executable host code with CSP and an authenticated bridge

One tested CSP-policy builder produces both a host-document policy and the stricter publication-rendering policy for Web and native. The static initial `reader.html` applies the versioned host meta policy before bootstrap/open; runtime manifest/hash/package-public synchronization additionally establishes the static-host asset set. The outer reader iframe deliberately has no required-CSP `csp` attribute, because that attribute blocks navigation of its stricter inner publication blob iframe. The host policy allows only the external same-origin bootstrap/module closure and Foliate-required local `blob:`/`data:` render resources; it uses no `unsafe-inline`, no `blob:` or `data:` script source, and no HTTP(S) `connect-src`. It denies form submission, popups, top navigation, external navigation, and unapproved framing. The host policy is not a substitute for publication CSP. On Web, only the inner publication iframe receives the strict publication policy as its `csp` embedded-enforcement policy, and only after the default-deny behavior probe succeeds inside the outer shell. It separately sets `script-src 'none'`, `connect-src 'none'`, and allows local `blob:`/`data:` image, style, font, and media rendering paths only. In particular, `'self'` is limited to reader bootstrap/modules in the host policy: publication documents never receive a `'self'` fetch permission that could reach arbitrary same-origin HTTP(S) URLs.

The policy builder is the sole source for CSP text and its tests assert that host and publication policies cannot drift across Web and native. Runtime link interception and manifest-script denial are defense in depth only; neither substitutes for the initial HTML CSP, browser-proven inner embedded enforcement, or strict publication policy. A missing, unreadable, or manifest-invalid host asset fails closed before a source is opened and reports an actionable runtime-asset error instead of silently falling back to application-document rendering. The browser probe is behavioral rather than feature detection and runs in the outer shell without required-CSP, so unsupported Firefox and Safari/WebKit implementations fail closed without publication I/O.

Both directions use a versioned, closed message schema containing message type, protocol version, reader session token, generation token, and command ID. A strict parser and shared wire corpus define exact type, field, direction, token length, command-ID, duplicate, and inflight semantics before either platform accepts a message. The parent posts only to `location.origin`; the iframe accepts an event only when `event.origin === location.origin`, `event.source === parent`, and the schema/session/generation are current. The parent applies the symmetric checks, including `event.source === iframe.contentWindow`. Unknown, malformed, wrong-origin, wrong-source, wrong-version, wrong-session, stale-generation, duplicate, and non-current-inflight messages have no UI, navigation, source, timeout, or callback effect. Private `File`/`Blob` payloads are accepted only in the authenticated `open` command and are not persisted as a public API representation.

Native WebView keeps JavaScript enabled only because Foliate itself is JavaScript. In secure-host mode, native code directly denies page-initiated navigation, popup/target-blank, download, file-chooser, geolocation, media-permission, and every unauthorized URL scheme. These decisions do not delegate to React Native callbacks, a secondary WebView, or `Linking`. File/content access stays denied except for audited reader-owned paths. Publication frames receive no React Native messaging object or command capability.

The native protocol is closed JSON named `hn-foliate-host`, version `1`. The adapter, never native code, generates every exactly-43-character base64url-random session, generation, and command ID; native code must reject missing or non-authoritative tokens and must not generate or silently bind replacements. Every message type has finite closed fields and size limits. `bind` is adapter-originated and has one cross-platform meaning: a valid matching acknowledgement means only that the bridge is bound; a duplicate matching acknowledgement, an acknowledgement for no longer-inflight binding, and stale traffic are no-ops; it is neither `ready` nor authority to read, prepare, transfer, or open a source. The fixed terminal protocol-violation outcome tears down the active port/relay. Publication `ready` belongs to 4D after actual renderer opening. The `hn-foliate-transfer` namespace is unknown and rejected during 4B. Wrong context, token, or generation traffic is silently ignored without changing timers or state; a schema violation from an authenticated current host is terminal; stale acknowledgements are ignored. Both iOS and Android validators consume the same strict parser/wire corpus and fail closed on invalid input or validator exceptions.

On iOS, a synthetic initial-CSP capability preflight runs before any publication URI/read/copy/prepare/transfer I/O. It proves that the selected iOS 14+ restricted-file host and isolated relay can establish the required initial-policy mechanism; failure is stable unsupported. Only after this preflight succeeds may 4C read or transfer a source. In 4D, before Foliate creates every untrusted publication document blob, the native host injects the strict initial publication CSP for EPUB HTML/XHTML/SVG, MOBI/KF8, FB2/FBZ, and CBZ content. Actual platform behavior probes must then demonstrate that script and same-origin/cross-origin request canaries are blocked under that initial policy before renderer open. `WKContentRuleList`, network blocking, load-after-meta insertion, and scrubbing are defense in depth only and cannot satisfy either gate. On Android, the equivalent embedded-CSP behavior probe and final private-bridge proof are mandatory; an old WebView that cannot supply them reports stable unsupported without source I/O.

Android serves native runtime resources only from a manifest-exact allowlist via `WebViewAssetLoader` at `https://appassets.androidplatform.net`. It canonicalizes and rejects Unicode/path/URL-confused requests, returns only explicitly declared MIME types with host CSP and `X-Content-Type-Options: nosniff`, and denies unknown paths with 404. The asset host CSP establishes runtime integrity only and never substitutes for the per-publication initial CSP. iOS exposes only reader-owned runtime and cache read roots, never arbitrary host file/content locations.

Alternatives considered:

- Disabling JavaScript globally: rejected because it prevents the Foliate renderer from operating.
- Sanitizing EPUB/HTML only: rejected because it does not cover other formats, blob-origin behavior, or all runtime resource paths.
- Relying on iframe sandbox only: rejected because Foliate documents WebKit behavior that makes script sandboxing insufficient for this threat model.

### 6. Make lifecycle, navigation, and flow renderer-owned and fail closed

The Web session lifecycle is explicitly `opening`, `live`, `disposing`, then terminal `disposed`. Each session owns exactly one iframe and is immutable: a source replacement or new source destroys the old iframe before it creates a fresh iframe/session, and a terminally disposed session rejects every late or attempted `open`. Every open, command, callback, timeout, and asynchronous TOC resolution captures the immutable session/generation. Source replacement first transitions the old session to `disposing`, cancels or rearms load/command timeouts for the new session, and makes late callbacks no-ops. Each late resource cleanup runs exactly once. Web disposal removes the complete iframe after attempting reader close in `try/catch`, destroying the Foliate book, revoking only reader-created blob URLs, and removing listeners. Cleanup remains idempotent even when the renderer open failed partway through; it never revokes the host-provided blob URL or touches a host URI.

The iframe sends model, ready, relocation, command acknowledgement, and categorized-error events only after normalizing Foliate state. Relocation is a closed structured-clone-safe DTO of finite primitives, strings, arrays, and plain objects only; it never contains a DOM `Range`, `Node`, document, element, or renderer-owned object. `ready` means the book has parsed and its first safe readable linear section has loaded under the publication policy; parse completion alone is not ready. It waits for async KF8 TOC fragment resolution before emitting a TOC destination result and drops that result if the generation changed. It derives non-wrapping Chrome navigation from readable linear sections and commands an exact section/destination rather than invoking page-level next/previous. A navigation acknowledgement follows a validated destination result and/or a matching relocation DTO; a rejected `goTo` promise alone is never confirmation. Flow state is read from the live renderer: fixed layout has no flow; for a reflow renderer an absent `flow` attribute means `paginated`, and a present flow changes on that renderer within the same session before its subsequent relocation reports the observable location.

Alternatives considered:

- Treating every Foliate relocation object or TOC link as synchronous: rejected because actual `relocate` data is delivered in event detail and KF8 fragment resolution can be asynchronous.
- Mapping Chrome navigation to Foliate paginator pages: rejected because a page is not the public linear-section contract.
- Inferring fixed/reflow behavior from detector output: rejected because the renderer's opened rendition is authoritative.

### 7. Keep default native scrolling and make pagination an explicit preference

The internal model records `scrolled` or `paginated` for reflowable books. Native sessions initialize `scrolled`; Web uses the documented product default selected during implementation and exposes the same flow control where applicable. `ReaderChrome` gains an accessible flow selector only when the book is reflowable. The active flow and Android limitation/recovery copy are observable through public UI and test identifiers.

The UI must say that Android pagination and text selection can be limited by the upstream WebView/Foliate multi-column stack, and the selector must leave `scrolled` available during the same source session. Tests verify switching and recovery controls, not a claim that selection or every CSS layout works in paginated Android WebView.

### 8. Replace the EPUB-specific acceptance surface atomically

The fixture directory and scripts will be renamed/reworked into a format-neutral corpus. Generated fixtures remain deterministic only where a small valid fixture can be authored safely; otherwise checked-in, legally redistributable fixtures have pinned provenance/checksum metadata. The matrix includes every supported format, malformed input, misleading labels, PDF, encrypted/DRM rejection where a lawful fixture is available, security payloads, navigation, flow behavior, and large-file measurement. Format-specific test data stays independent so changing EPUB recipes cannot alter another format's expected bytes.

All old imports, dependencies, PNPM overrides, patches, engine staging tests, fixture scripts, consumer fixtures, manifests, notices, and docs are removed or rewritten in the same implementation change. A repository scan plus packed-artifact and clean-consumer checks prevent retired engine references from surviving transitively in project-owned artifacts.

### 9. Layer Web evidence without treating the release gate as complete

Stage 3 records two distinct evidence layers. The completed automated Web baseline is limited to CFT Chromium actual rendering of EPUB, FB2, FBZ, fixed-layout CBZ, MOBI6, and single-section KF8; Chromium behavioral-probe evidence; Firefox fail-closed evidence; runtime sync/check; Expo static Web export; packed-consumer sync/export; strict inner publication CSP with no outer host `csp` attribute; and differential probe coverage for bridge authentication, linear navigation, TOC, flow, and source replacement. The MOBI6/KF8 scope is explicitly limited to the verified single-section fixtures where applicable. This baseline is sufficient to close the implemented Web-adapter tasks and to begin the independent Stage 4 native work.

The release/platform acceptance gate remains open until it obtains separately recorded evidence from real branded Edge, real macOS Safari, and real iOS Safari; a browser E2E for `runtime-asset-missing`; an `expo start --web` development-server smoke; and either a controlled temporary-directory reproduction of the complete package raw gate or a formal infrastructure exception. Playwright WebKit does not satisfy either Safari requirement. An open gate is not an acceptance pass and must remain visible in the final release gate, but it is not a dependency for starting Stage 4.

### 10. Gate native work in dependency order

Stage 4 proceeds only in five ordered groups: 4A establishes the native asset host and Android capability proof; 4B establishes the adapter-authoritative, ABI-preserving iOS 14+ and Android private bridge/protocol skeleton plus iOS synthetic initial-CSP preflight, with `bind`/acknowledgement/terminal/no-op behavior only and without source I/O, transfer, renderer opening, or `ready`; 4C prepares and transfers bounded source bytes only after 4B preflight succeeds; 4D injects the actual publication CSP, runs renderer behavior probes, then bootstraps Foliate and applies renderer flow; and 4E proves lifecycle and platform evidence. A later group cannot relax or bypass an earlier failure. In particular, an iOS preflight or Android final-bridge/embedded-CSP failure is stable unsupported before copying or reading a source; it is not repaired by fallback bridge, asset, network, rule-list, post-load-meta, or scrub behavior.

## Risks / Trade-offs

- [Foliate has no stable release API] -> Pin the exact Git revision, generate assets only from its submodule, verify the gitlink in CI, and require explicit revision-review evidence for upgrades.
- [CSP blocks necessary Foliate blob/module paths] -> Start from a minimal tested policy per host, include security fixtures that prove both local rendering and blocked remote/script behavior, and prohibit broad directive relaxations without a new security review.
- [Android WebView paginated layout/selection defects] -> Default to `scrolled`, show recovery guidance and a flow switch, and scope tests to supported fallback behavior rather than visual perfection claims.
- [Native URI access conflicts with secure-WebView default-deny policy] -> Pass only reader-owned prepared content through an audited path, clean it deterministically, and test that host URIs are never deleted or opened as arbitrary WebView file URLs.
- [Format parsers differ in TOC/location fidelity] -> Normalize only the capabilities actually supplied by each book, make TOC optional, preserve location on failed navigation, and record format-specific fixture expectations.
- [Submodule initialization is missed in consumer/CI environments] -> Make verification fail early with an actionable submodule command and ensure package builds consume generated assets rather than a developer's untracked source tree.
- [A public runtime is present for the Demo but missing for a packed consumer] -> Make sync/check project-root-specific, run it before every Web command, and exercise an exported app and a separately installed packed consumer.
- [Same-origin iframe messaging is mistaken for trusted messaging] -> Bind both directions to exact origin, `WindowProxy` source, protocol version, session, and generation, then exercise adversarial messages and replacement races in browser E2E.
- [A browser advertises iframe CSP but does not enforce it] -> Run the default-deny inner-frame behavior probe in the outer shell without required-CSP, require it to block script plus same-origin/cross-origin request canaries before any publication URI is accessed, and fail closed with an unsupported-browser error otherwise.
- [A native WebView has incomplete bridge or CSP support] -> Gate before source I/O, require iOS 14+ restricted-file-origin/named-world relay proof or Android final private-port proof, exact main-frame/current-host identity, and behavior-proven initial publication CSP, and return stable unsupported rather than using page-world, `addJavascriptInterface`, wildcard, or post-load fallbacks.
- [A native transfer exhausts memory or is confused across sessions] -> Limit native sources to 32 MiB and bind finite, digest-verified, strictly ordered chunks to session/generation/transfer ID; reject every invalid or aborted transfer before session creation.

## Migration Plan

1. Add and pin the submodule plus the verification/asset-generation path before changing a runtime adapter; record its license and revision review.
2. Generate the Web reader runtime/manifest, synchronize it into the workspace host `public/reader/`, and make the sync/check gate run before development and export.
3. Introduce the Chromium-only behavior-proven embedded-CSP gate, private Foliate host protocol, content-aware detection, shared CSP-policy builder, and common model while retaining the existing public root entrypoint and `ReaderChrome` surface.
4. Establish the ordered native 4A-4E security gate: capability proof, iOS 14+ or Android private bridge skeleton and iOS synthetic preflight, bounded transfer, behavior-proven publication bootstrap, renderer flow, and lifecycle evidence before opening a native source.
5. Upgrade the Demo picker, format-neutral fixture corpus, tests, root commands, and documentation; verify workspace development, exported Demo, packed consumer, browser E2E, and native bundle/export separately.
6. Complete the separately tracked real-platform/release gate before release: real branded Edge, real macOS Safari, real iOS Safari, `runtime-asset-missing` browser E2E, `expo start --web` smoke, and complete package raw-gate evidence or a formal infrastructure exception. This gate may remain open while Stage 4 begins, but it cannot be represented as release acceptance.
7. Roll back a failed release by restoring the prior package revision and its lockfile/submodule gitlink as one coherent revision. Do not mix a Foliate asset bundle with a different source gitlink. A source-format API migration has no runtime compatibility shim beyond the documented replacement contract.

## Open Questions

None. The selected Foliate revision, supported formats, PDF exclusion, Chromium-only browser security boundary, default native flow, Android fallback expectation, and validation boundary are fixed by the approved product decision.
